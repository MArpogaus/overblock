#+TITLE: How overblock works
#+OPTIONS: toc:2

This document describes the API and the implementation of the layer.
The [[file:../README.org][README]] tells you how to install and use
the packages. The four packages on this layer have notes of their own:
[[file:overblock-md.org][overblock-md]],
[[file:overblock-pydoc.org][overblock-pydoc]],
[[file:overblock-pycell.org][overblock-pycell]] and
[[file:overblock-rmd.org][overblock-rmd]].

The text uses these terms:

- *block*: what the layer shows over a region of the buffer, or after
  it.
- *anchor*: the overlay that covers the region and holds the state.
- *caller*: the package that renders the text. The layer renders
  nothing.
- *piece*: one line of a rendering, on one line of the source.
- *notebook*: a buffer of regions and a shell to send them to. Two of
  the packages here are notebooks, and =overblock-run.el= is the loop
  they share.

* The block layer

A caller renders text and gives it to =overblock-show=, which returns
the block:

#+begin_src emacs-lisp
  (overblock-show BEG END
                  :kind 'result          ; whose block this is
                  :data ANYTHING         ; what the caller keeps with it
                  :over TEXT             ; shown instead of the region
                  :indent N              ; columns left in view on later lines
                  :body TEXT             ; shown after the region
                  :header TEXT           ; shown above the body
                  :hidden t              ; show nothing for now
                  :keymap MAP :help-echo STRING
                  :attached OVERLAYS)    ; the caller's own
#+end_src

- =:kind= tells the blocks of one caller from those of another. A block
  without a kind is anonymous.
- =:data= belongs to the caller. The layer keeps it and never reads it.
- =:over= puts each line of the rendering on the source line it came
  from. A source line that carries nothing goes under a cloak. A blank
  line that takes a gap of the rendering stays in view. Thus a tall
  rendering scrolls like text.
- =:indent= keeps that many columns of each line after the first in
  view under the rendering. The first row starts where the block
  starts.
- =:body= is on the newline that ends the region, and =:header= is above
  it.

A new block replaces the blocks of its own kind in the same region. A
block without a kind replaces the blocks of each kind. The layer never
calls a renderer.

| Function                         | What it does                                |
|----------------------------------+---------------------------------------------|
| =overblock-show=                 | show a block, and return it                 |
| =overblock-show-rendering=       | show a rendering over its source            |
| =overblock-get=, =overblock-set= | read and write a property of a block        |
| =overblock-refresh=              | show a block again from its properties      |
| =overblock-in=, =overblock-at=   | the blocks of a region, or the one at point |
| =overblock-delete=               | remove one block                            |
| =overblock-clear=                | remove the blocks of a region               |
| =overblock-take-down=            | remove a block as its caller asked          |
| =overblock-sweep-orphans=        | remove what an edit left without an anchor  |
| =overblock-stale-when-edited=    | remove a block on the next edit under it    |
| =overblock-goto-event=           | select the window of a click and go there   |
| =overblock-only-in=              | keep a minor mode off in other major modes  |

The anchor covers the region and holds the properties. It stops before
the newline that ends the region. Thus a window that starts at the next
line keeps the block out of view. A second overlay covers that newline
and carries what shows after it.

=overblock-refresh= makes all that a block shows again from its
properties. Thus a fold is =:hidden= and =overblock-refresh=, and
nothing is saved and given back.

The buffer text never changes. Where the region ends without a
newline, the body goes on the anchor.

** Images

Display properties do not nest, so images need care.

| Function                | What it does                                             |
|-------------------------+----------------------------------------------------------|
| =overblock-image-in=    | whether a rendering holds an image                       |
| =overblock-image-cap=   | cap each image to =overblock-image-height= of the window |
| =overblock-image-label= | put the labels in place of the images, for a terminal    |
| =overblock-flattened=   | turn the pixel spaces of another window into spaces      |
| =overblock-fill-props=  | add properties only where the rendering has none         |

=overblock-fill-props= keeps the keymap of a link, because it writes
only where the rendering has no property of its own.

** Where each row goes

These rules are for a graphic frame:

- The header is a string of its own. A bar puts its icons at the
  window edge with =(space :align-to (- right ...))=, and a display
  property ignores that spec.
- A plain body is on the =display= property of the newline, which
  costs least.
- A body with an image cannot be on a display property, because the
  image would not show. Such a body joins the header on the
  =after-string= of the anchor. The newline stays visible, or the
  wheel cannot pass the block.
- The first row starts a new line only where its newline does not
  already begin a line. Thus a region that ends in a blank line gives
  that line to its header.

** Text shown over a region

Each line of a rendering goes to the source line it came from. The two
share their first letters and digits once the markup is gone, and
=overblock--key= is that key. A source line that renders to nothing,
such as an underline, a fence or a table rule, goes under the cloak. A
rendered line that matches no line near stays on the line before it,
which keeps a wrapped line together. A blank line of the rendering
falls on a blank line of the source where one comes next.
=overblock--no-false-gap= removes a blank line that shr puts after a
heading where the source has none. The first source line always
carries a line where it cannot go under a cloak: where it begins the
buffer, or begins inside a line. Elsewhere it carries nothing when its
line belongs to a later source line. Thus a fence in the middle of a
file carries no line of code.

Where fewer than half of the source lines with text match a rendered
line, the rendering is not line by line. A source line that the
renderer wraps still counts once. The lines of the rendering are then
dealt evenly over the source lines with text. A longer
rendering loses its blank lines first, and the blank lines of the
source stay in view as gaps. A blank line in view also keeps the wheel
moving.

A cloak is an invisible overlay that starts at the newline of the line
above. An invisible run that starts inside a line, or a line of no
height, stops =scroll-down= with a =beginning-of-buffer= error.

A piece with an image cannot be on a display property. Such a piece
hides its line with an empty display string and is on the
=before-string=, which can show images. It is not on the
=after-string=, because Emacs leaves out an overlay string that starts
inside invisible text. The line keeps its own row, so a rendering with
an image scrolls one line at a time.

** What an edit takes down

=overblock-stale-when-edited= puts three hooks on a block:

- =modification-hooks= runs for a change inside the overlay.
- =insert-in-front-hooks= runs for an insertion at its first character.
- =insert-behind-hooks= runs for an insertion at its end.

The anchor stops before the newline of its region. Thus text typed at
the end of the last line is an insertion at the end, and only the third
hook sees it.

=overblock-sweep-orphans= removes the pieces that stay when an edit
cuts the text out from under a block.

** The image cap

=overblock-image-height= caps an inline image at a share of the
window. A block taller than the window stops the wheel, which goes back
and starts again. An image with its own =:max-height= keeps it. A
=:height= wins over =:max-height= in Emacs, so the layer brings an
image with a =:height= over the limit down to it, and its =:width= in
proportion.

The share comes from the window that shows the buffer. Where no window
shows it, the share comes from the selected window.

Emacs 31 cuts an image taller than =shr-sliced-image-height= into
slices, one for each line of the window it was rendered in. A slice
does not make an image smaller, and the slice fractions apply to the
original height. Thus the layer joins the slices of one image into the
whole image again, and caps it.

* The header bars

Each bar of each package has one shape. It has an icon, a space, a word
for what the bar stands on, and the buttons at the right edge.

| Function                 | What it does                                           |
|--------------------------+--------------------------------------------------------|
| =overblock-bar=          | the row: glyph, label, and the icons at the right edge |
| =overblock-bar-over=     | an overlay that shows a bar in place of a line         |
| =overblock-bar-draw=     | draw a bar on such an overlay                          |
| =overblock-bar-line=     | find or make the bar of a line, and draw it            |
| =overblock-bar-in=       | the bar that covers part of a region                   |
| =overblock-bars=         | the bars of the buffer                                 |
| =overblock-bar-kind=     | what a bar was drawn as, or nil for no bar             |
| =overblock-bar-stale=    | make a bar forget what it was drawn from               |
| =overblock-bars-stale=   | the same for each bar of the buffer                    |
| =overblock-buttons=      | the icon group from a list of descriptors              |
| =overblock-button=       | one button                                             |
| =overblock-button-type=  | the customize type of a list of descriptors            |
| =overblock-glyph=        | the first of several candidates the frame can draw     |
| =overblock-window-width= | the width of the narrowest window of the buffer        |

A bar on a line of the buffer, such as a notebook cell line or an R
chunk header, goes through =overblock-bar-line=. A bar that is a row of
a rendering, such as the bar of a doc string, calls =overblock-bar=
with the column of its indent.

A line of the buffer gets a =(space :align-to (- right (N)))= stretch.
A row of a rendering cannot use a stretch, because a display property
inside a display string does not show. Thus =overblock--bar-padded=
counts the room in pixels and fills it with spaces.

** Buttons

Each descriptor is =(KEY GLYPHS HELP COMMAND WHEN)=:

- KEY names the button. Nothing reads it.
- GLYPHS are the candidates for the label. The first one that the frame
  can draw wins. Keep a plain word at the end, because each frame can
  draw the last label.
- HELP is the tooltip.
- COMMAND runs on a click, with the click in =last-input-event=.
- WHEN is =t=, =image=, =lines=, =running= or =done=. The button then
  shows always, with an image, with output, while the region runs, or
  when the run has ended.

Use three candidates: a codicon of a nerd font, a character of an
ordinary monospace font, and a short word. Keep the plain candidates
of different buttons different. Two buttons with the same character
are one button to a reader.

Emacs can ask a font what it holds, but not a terminal. Thus a terminal
gets the last candidate. A reader whose terminal has the icon font sets
=overblock-terminal-glyphs=. The coding system is still asked, so a
terminal that cannot encode a candidate never gets it.

=overblock-glyph= keeps its answers in a table, by the font of the frame
and the candidates. The answer cannot change while the frame keeps its
font.

** A bar in place of a line

=overblock-bar-over= makes the overlay and =overblock-bar-draw= draws
on it. All of the bar but its last character is on the
=before-string=. The last character is the =display= in place of the
line text, and carries =cursor=.

Both halves are necessary:

- The bar must be an overlay string, because a display string ignores
  =(space :align-to (- right ...))=.
- The caret needs a glyph to draw on. Over an empty display string,
  point can be on the line with nothing to show it, and the line
  cannot be folded from.

The bar is never on the =after-string=. That string draws at the end of
the overlay, and the cloak of a rendering can cover that place.

=overblock-bar-draw= rebuilds a bar only when the text of its line,
its glyph, its label or its icons change. Thus a caller can draw from a
change hook. A change of width marks each bar stale through
=overblock-bar-stale=.

** A column of slack

=overblock-bar= keeps the buttons one column short of the right edge
in a graphic frame, and three columns short in a terminal. A row that
ends at the edge can wrap at one redisplay and not at the next. The
third column of a terminal keeps room for the ellipsis of an outline
fold.

** Point on the line

A bar stays where it is, wherever point is. Thus the buffer does not
move when point crosses the line, and a button press does not land on
the text under the bar.

The line is still there to edit. Point can be on it, the caret shows on
the last glyph of the bar, and the label follows what is written on the
line. Folding works from there.

The commands are on =<down-mouse-1>=. Thus the press runs the command
before a redraw can change what is under the pointer. When Emacs reads
the release, it clears the echo area, so =<mouse-1>= and
=<drag-mouse-1>= say the newest message again where the command said
one.

** The width a bar is cut to

=overblock-window-width= gives the width of the narrowest *visible*
window that shows the buffer. An invisible or iconified frame does not
count.

A buffer in no visible window is not cut at all. The cut is part of the
string, and no window means no width to cut to. A block drawn while no
window shows its buffer makes the buffer forget its width. Thus the
next window that shows the buffer draws it again.

The measurement keeps point. =window-max-chars-per-line= selects the
window that it measures, which sets the point of the buffer to that
window's point.

* The live cycle

=overblock-live-start= runs a mode that keeps a buffer rendered and
editable. The caller gives the kind of its blocks and a render
function:

#+begin_src emacs-lisp
  (overblock-live-start 'my-kind #'my-render-buffer)
#+end_src

The render function takes no arguments. The layer calls it once at the
start, and again when the reader stops for =overblock-live-idle=
seconds. A mode that sends a whole buffer through one converter does
so from this one function.

| Function or variable             | What it does                                    |
|----------------------------------+-------------------------------------------------|
| =overblock-live-start=           | start the cycle in this buffer                  |
| =overblock-live-stop=            | stop the cycle of a kind, and remove its blocks |
| =overblock-live-wanted-p=        | whether a region still wants a rendering        |
| =overblock-live-edit=            | show the source of the region at point or click |
| =overblock-live-drop-if=         | remove the live blocks that a predicate selects |
| =overblock-live-source-at-point= | whether the region at point always shows source |
| =overblock-width-functions=      | what to call when the buffer changes width      |

The render function must leave alone each region for which
=overblock-live-wanted-p= is nil:

- A region that has a rendering.
- A region that the active region reaches.
- The region of the reader. With =overblock-live-source-at-point= t,
  this is the region point is in. With nil, it is the region point is
  in, while point stays in the text that a rendering last came off.

=overblock-md-preview-mode= keeps the default t. =overblock-pydoc= and
=overblock-pycell= set it nil, because the reader works in the
rendering.

A rendering comes off when the reader clicks it and when the text
under it changes. Point that moves to a rendering does not remove it.
Thus the text does not grow and shrink under a scroll. A marked region
shows the source of the renderings that it reaches, so the reader
copies the source.

The cycle also watches the width. =overblock--width-changed= runs from
=window-configuration-change-hook= and =text-scale-mode-hook=. When the
columns change, it removes the blocks made for another width, marks
each bar stale and runs =overblock-width-functions=. The cycle then
renders the blocks again. It does not render at once, so a drag of the
window edge starts no converter at each column.

* The edit buffer

=overblock-edit-in-buffer= opens the text under a block in a buffer of
its own, as =org-edit-special= opens a source block. It takes the
region and a plist:

| Key      | What it gives                                        |
|----------+------------------------------------------------------|
| =:name=  | the name of the edit buffer, with a line number      |
| =:label= | the word for the thing, for the header line          |
| =:mode=  | the major mode of the edit buffer                    |
| =:text=  | a function of BEG and END that gives the plain text  |
| =:put=   | a function of BEG, END and the text that writes back |

=overblock-edit-commit= (=C-c C-c=) writes the text back, and
=overblock-edit-abort= (=C-c C-k=) discards it. The keys are in
=overblock-edit-mode-map=, as in =org-edit-special=.

Each region has its own buffer. Thus the text of a second region does
not replace the edit of the first.

An edit of the same region that is still open is given back, and not a
new copy of the file text. It must be the same region, and not only the
same name. A name carries a line number, and two regions can be on that
line at different times. When the open edit is of another region, the
reader must say whether to discard it. The region is held by markers, so
a commit lands on it after the source changed above it. Text typed right
after the region while the edit is open is not part of the region, and
the commit keeps it.

* The output of a shell

A copy of shell output carries the keymap of the shell and alignment for
another window. It also carries a live vtable of that buffer, and images
at their own size. =overblock-repl-detach= makes a copy that a block can
show:

#+begin_src emacs-lisp
  (overblock-repl-detach (buffer-substring beg end))
#+end_src

It changes three things:

- *The stretches.* comint-mime renders a DataFrame as a vtable, which
  sets the width of a space in pixels for the window of the shell. shr
  also aligns with pixels. Each stretch becomes as many real spaces as
  it is characters wide. A vtable measures its header in its own face,
  so a header label can stand one column left of its data.
- *The table.* The copy keeps the table object in the
  =overblock-repl-table= text property. The layer lays the table out
  again in characters, each column as wide as its widest cell, with the
  column names in bold. =overblock-repl-table-copy= gives the object to
  a caller, which can draw a live table with =vtable-insert=.
- *The keymap.* The copy loses the keymap of the shell. A block must
  not offer a click that it cannot answer.

| Function                               | What it does                                    |
|----------------------------------------+-------------------------------------------------|
| =overblock-repl-detach=                | a copy of shell output that a block can show    |
| =overblock-repl-table-copy=            | the table object of a copy, for a live table    |
| =overblock-repl-first-lines=           | the head of an output, without reading the rest |
| =overblock-repl-count-lines=           | the lines of an output                          |
| =overblock-repl-strip-trailing-prompt= | remove the prompt at the end of an output       |

=overblock-repl-first-lines= stops at its limit, and a limit of zero
reads every line. To cap the images is the work of
=overblock-image-cap=. The file needs =vtable=, which Emacs ships.

* The run loop

A notebook sends a region to a shell, watches the output, waits for
the prompt, and shows the output under the region. This loop is the
same for each language, so it is in one file. =overblock-run.el= holds
the run state, the queue of a pass, the ticker, the process filter and
the result block. =overblock-pycell= sends Python cells with it, and
=overblock-rmd= sends R chunks.

** The backend

Nothing in the file knows a language. One plist, the *backend*, tells
what the language is. =overblock-run-attach= sets it as the
buffer-local =overblock-run-backend=, and =overblock-run-detach= removes
it.

The shell and the regions:

| Slot         | Signature        | What it answers                                   |
|--------------+------------------+---------------------------------------------------|
| =:name=      | string           | the word that messages carry                      |
| =:unit=      | string           | what a region is called: "cell", "chunk"          |
| =:process=   | () → process     | the live shell process, or nil                    |
| =:start=     | () → process     | start a shell; nil where it prompts later         |
| =:arm=       | (THUNK)          | run THUNK on a first prompt; optional             |
| =:send=      | (PROC BEG END)   | send the region to the process                    |
| =:prompt-p=  | (TAIL) → boolean | whether the output ends at a prompt               |
| =:clean=     | (TEXT) → string  | the output as a block can show it                 |
| =:error-p=   | (TEXT) → boolean | whether the region failed, which stops a pass     |
| =:step=      | () → boolean     | run what is at point, and say whether to wait     |
| =:region-at= | () → cons        | the region point is in, as =(BEG . END)=          |
| =:starts=    | () → markers     | a marker at the start of each region, in order    |
| =:redraw=    | ()               | draw the bars of the mode again; optional         |

Where =:error-p= says that the region failed, the bar of its result
says =error=.

The look of a result block:

| Slot       | What it holds                                                                                             |
|------------+-----------------------------------------------------------------------------------------------------------|
| =:buttons= | the symbol of the option that holds the button descriptors                                                |
| =:stale=   | a function of each new result block that makes it go on an edit; =overblock-stale-when-edited= by default |

=:buttons= names an option and does not copy its value. Thus a button
list that the reader changes shows at the next draw. The bar wears the
face =overblock-bar= and the body =overblock-body= in each notebook. The
result limits are the options =overblock-run-max-lines= and
=overblock-run-max-line-length=, one pair for both notebooks.
=overblock-run-result-buttons= gives the five buttons that each result
carries, with the words of the unit.

A send copies the backend into the shell buffer. The filter and the
ticker run there, and must get the same answers. Thus the head of a
running output is read in the shell buffer, cut to the result limits.

| =overblock-run-region=         | run one region, and start the shell where there is none      |
| =overblock-run-cells=          | run several regions in order, to the first error             |
| =overblock-run-on-prompt=      | queue regions to run when a new shell prompts                |

| =overblock-run-shell=          | the buffer that holds the queue and the run state            |
| =overblock-run-running-region= | the region that runs now                                     |
| =overblock-run-go-home=        | put point and the view back where the pass was asked for     |
| =overblock-run-show=           | draw a result                                                |
| =overblock-run-update=         | draw a result again                                          |
| =overblock-run-header=         | the bar of a result                                          |

The commands of a result are the same in each notebook:
=overblock-run-toggle-output=, =overblock-run-copy-output=,
=overblock-run-pop-output=, =overblock-run-save-image=,
=overblock-run-discard-output=, =overblock-run-clear-results=,
=overblock-run-above=, =overblock-run-below=, =overblock-run-stop= and
=overblock-run-interrupt=. Each package keeps its own buttons and the
commands that know its regions.

** The queue is in the shell buffer

The queue of a pass and the state of the running region are in the
buffer of the shell. Thus a notebook with a shell of its own has a
queue of its own, and a pass in one notebook does not touch another.
=overblock-run-shell= gives that buffer. Each part of the runner gets
to the queue through it.

=overblock-run-next= is a loop, and does not call back into the command
that runs one region. A recursion would build a frame for each markdown
cell in a row, and each frame would run its tail on the way out.

With =overblock-run-scroll=, each region of a pass goes to the top of
each window that shows the notebook, so the code that runs is visible,
and =overblock-run-go-home= puts point and the view of each window
back when the pass ends. Where a minibuffer is open, this occurs after
it closes, because its exit gives the windows back as they were. A
restart ends the pass the same way. While a minibuffer is open, a step
moves neither point nor the windows, and the next region catches up.
With the option nil, a pass never scrolls. A single region does not
start the scrolling, also when it waits on the queue. A region that
joins a scrolling pass goes with it. A pass that joins a waiting
region or a pass that no longer scrolls, in its own notebook, takes
over the home and scrolls.

The scrolling stops at the first command of the reader that scrolls a
window of the notebook or moves point in it. Only a command counts:
redisplay moves a window start for =scroll-margin=, and output arrives
between commands. Thus =pre-command-hook= notes each window of the
notebook, and =post-command-hook= compares. Commands in a minibuffer
are not noted or compared: its exit gives the windows back, so the
command that opened it counts as one. Once stopped, the pass leaves
point and the windows alone, to its end.

At its end, the pass says =NAME: done=, with the =:name= of the
backend. A failed region ends the pass with =NAME: stopped at error=.
A single region sent to a free shell says neither message. A region
that waited on the queue, behind a busy shell or a starting
interpreter, also ends its pass with =NAME: done=, or =NAME: stopped
at error=. The home marker is in the shell buffer too, and is set when
the shell exists.

A region sent while the shell is busy or starting waits in the queue,
and runs as it was sent. A pass asked for then also goes behind the
queue. Each request queues what it asks for, as in Jupyter: a region
asked for twice runs twice, in the order asked.

** What the ticker reads

A ticker runs five times a second while a region runs. It reads only
the head of the output, because the block shows only the head.
=overblock-run-output-head= keeps the text when each line that shows
has arrived, and later ticks read nothing. =overblock-run-total=
counts only the new lines, and keeps its position in the run state.
Thus the cost of a tick does not grow with the output. When the region
ends, one full read makes the result and the line count exact.

=overblock-run-follow= writes only the new output into a buffer that
follows a running region. When the region ends, it writes the whole
output once more.

** When a prompt will never come

=overblock-run-abort= ends the running region as a death. The result
gets a note, with the exit status where there is one, after the output
received so far. It runs for a dead interpreter, which the ticker
finds, for a killed shell buffer, and for a restart, which runs the
major mode again. Thus the shell carries =kill-buffer-hook= and
=change-major-mode-hook= as well. Without the abort, a block keeps a
running header with a still spinner and stopwatch.

* Scrolling

A body is one buffer line, because it is one display string.
=next-line= and =previous-line= cross it in one step. A window can
start only at a buffer position.

A body with an image is on the after-string of the anchor, and a window
cannot start inside an overlay string. Thus:

- The wheel does not cross the block the same way in both directions.
  A block with an image ends lower than it started after a series of
  crossings.
- A block taller than the window throws the wheel back. See
  [[#the-image-cap][the image cap]].
- =scroll-up-line= does not pass such a block at all.

=scroll-up=, =scroll-down=, =next-line= and a folded block pass.

Two scroll settings matter. Without =pixel-scroll-precision-mode=, the
wheel crosses a block in one step. With =scroll-conservatively= above
100, redisplay must not recenter, and two blocks taller than the window
can pass the window between them with no end. A =scroll-margin= of 1 or
more also stops this.

** The cost of a rendering

A rendering makes each scroll event more expensive. The cost comes
from the face runs and not from the height. Rendered markup holds
several hundred face runs in a line, and source code holds a few. Plain
text of many lines scrolls as fast as none.

* What the hot paths do

- =overblock-glyph= keeps its answers by font and candidates, and does
  not ask =internal-char-font= again on each tick.
- =overblock--pieces= takes its lines off a walking list. The match of
  a line looks four source lines ahead, so its cost is linear in the
  lines of a region.
- =overblock-fill-props= takes a plist and walks the rendering once.
- =overblock-run-show= keeps the block that it has when only the data
  changed, which is each tick of a growing output.
- =overblock-repl-first-lines= and =overblock-repl-count-lines= are
  bounded.

* The tests

=make test= runs the batch suites, one for each file. A test is in the
suite of the code that it checks. These suites belong to the layer:

- =test/overblock-test.el=: the slot of each row, the line break of the
  first row, and a hidden block. It also tests blocks of two kinds in
  one region, what a delete removes, the cloak of the last line and the
  sweep. Other tests check the image cap, the slices, and the bars,
  buttons and glyphs.
- =test/overblock-repl-test.el=: a copied table laid out again, and its
  getter.
- =test/overblock-run-test.el=: the runner with a process at the other
  end and no language. Its backend is a plist over =cat=. It tests a
  prompt that ends a run, an error that stops a pass, and a dead, killed
  or restarted shell. It also tests the queue, the follower, and the
  buttons that both notebooks draw.

The notebook suites test the runner from above, and =make test-live=
sends real regions to a real IPython and a real R.

=test/overblock-client-test.el= is a caller of another shape. It renders
the math of a Python doc string over its lines, with no process and no
mode. It checks that such a caller needs nothing more from the layer.
It uses the renderer of overblock-md.

The notes of the other four packages list their suites. A fifth of all
tests render markup, and skip where no converter is installed.
=make test STRICT=1= makes such a skip a failure, and the CI sets it.
