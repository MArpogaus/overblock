** About The Project

This repository holds five Emacs packages with one idea. A *block*
shows text over a region of a buffer, or after it. The buffer text does
not change, so files, undo and a language server see nothing.

A block that shows text over a region puts each rendered line on the
source line it came from. Thus a tall rendering scrolls like text and
does not jump past in one step.

The four modes render Markdown in place, and show Python doc strings
as documentation. They also show the output of a Python cell or an R
chunk under its code.

[[file:img/demo.gif]]

The animation shows the four modes in turn. It shows a Markdown file,
the doc strings of a Python module, a =# %%= notebook and an =.Rmd=
file. A real Emacs session recorded it with the setup in
[[file:demo/init.el][=demo/init.el=]].
[[file:demo/README.org][=demo/README.org=]] tells how to record it
again.

** Which One Do You Want

| Package            | What you get                                      | It needs                                                         |
|--------------------+---------------------------------------------------+------------------------------------------------------------------|
| =overblock=        | the layer, a library for other packages           | Emacs 29.1                                                       |
| =overblock-md=     | markup rendered to text, and a Markdown preview   | =overblock=, latex-to-svg-backend; markdown-mode for the preview |
| =overblock-pydoc=  | Python doc strings rendered in place              | =overblock=, =overblock-md=                                      |
| =overblock-pycell= | inline results for =# %%= Python cells            | =overblock=, =overblock-md=, code-cells                          |
| =overblock-rmd=    | inline results for the R chunks of an =.Rmd= file | =overblock=, =overblock-md=, ESS, markdown-mode                  |

No package is on MELPA yet. Thus a package manager cannot find the
packages of this repository by name. Each package that you use needs a
recipe of its own, and so does each package of this repository that it
needs. Declare them from the bottom up: =overblock= first, then
=overblock-md=, then the mode. Leave out the =:hook= of overblock-md
where you do not want the preview.

The snippets below are for [[https://github.com/progfolio/elpaca][elpaca]]
and =use-package=. Each recipe gives its package a clone of its own with
=:repo ("MArpogaus/overblock" . "NAME")=. Two packages in one clone
can make elpaca hang. Install the other dependencies, such as
latex-to-svg-backend or code-cells, as usual.

For plain Emacs or package.el, put a clone on the load path. Install
the dependencies with package.el, so that their autoloads load. Leave
out the lines of each package that you do not use.

#+begin_src emacs-lisp
  (add-to-list 'load-path "/path/to/overblock")

  (require 'overblock-md-preview)
  (add-hook 'markdown-mode-hook #'overblock-md-preview-mode)

  (require 'overblock-pydoc)
  (add-hook 'python-base-mode-hook #'overblock-pydoc-mode)

  (require 'overblock-pycell)                                    ; only with code-cells
  (add-hook 'python-base-mode-hook #'code-cells-mode-maybe)      ; only with code-cells
  (add-hook 'code-cells-mode-hook #'overblock-pycell-mode-maybe) ; only with code-cells
  (add-hook 'inferior-python-mode-hook #'comint-mime-setup)      ; only with comint-mime

  (require 'overblock-rmd)                                       ; only with ESS
  (add-to-list 'auto-mode-alist '("\\.[rR]md\\'" . markdown-mode)) ; only with ESS
  (add-hook 'markdown-mode-hook #'overblock-rmd-mode-maybe)      ; only with ESS
#+end_src

[[*overblock-pycell: Python notebook cells][overblock-pycell]] gives the
IPython settings.

No package installs a hook or binds a key in your buffers. Installing a
package does not change how Emacs behaves.

** overblock: the block layer

=overblock= shows blocks and knows nothing about a language, a cell or
markup. It also holds the run loop that the two notebooks share. It
shows nothing by itself, so install it when another package needs it:

#+begin_src emacs-lisp
  (use-package overblock
    :ensure (overblock :host github
                       :repo ("MArpogaus/overblock" . "overblock")
                       :files ("overblock.el" "overblock-repl.el"
                               "overblock-run.el")))
#+end_src

[[file:docs/overblock.org::*Use][Use]] in docs/overblock.org tells how
to change what every package shows. The API for a package that shows
blocks is in [[file:docs/overblock.org][docs/overblock.org]].
[[file:docs/custom-mode.org][docs/custom-mode.org]] tells how to write
a mode of your own, with two small example modes.

** overblock-md: markup rendered to text

[[file:img/overblock-md.gif]]

=overblock-md= turns Markdown into one propertized string. A converter
writes HTML, and shr renders it. LaTeX formulas become images through
[[https://github.com/alberti42/latex-to-svg-backend][latex-to-svg-backend]].
The package also holds =overblock-md-preview-mode=, which shows a
Markdown buffer rendered over its own source.

#+begin_src emacs-lisp
  (use-package markdown-mode :ensure t)

  (use-package overblock-md
    :ensure (overblock-md :host github
                          :repo ("MArpogaus/overblock" . "overblock-md")
                          :files ("overblock-md.el"
                                  "overblock-md-preview.el"))
    :hook (markdown-mode . overblock-md-preview-mode))
#+end_src

The hook turns the preview on in each Markdown buffer. Without the
hook, use =M-x overblock-md-preview-mode=.

[[file:docs/overblock-md.org::*Use][Use]] in docs/overblock-md.org
tells the commands and the options. It also tells how eglot shows the
documentation of a language server with this package.

** overblock-pydoc: Python doc strings

[[file:img/overblock-pydoc.gif]]

=overblock-pydoc-mode= shows the doc strings of a Python buffer as
documentation. The quotes and the indentation go, the markup renders,
and the code stays as it is. A click on a doc string shows its source.
Point that moves into a doc string changes nothing.

It works in =python-mode= and in =python-ts-mode=.

#+begin_src emacs-lisp
  (use-package overblock-pydoc
    :ensure (overblock-pydoc :host github
                             :repo ("MArpogaus/overblock" . "overblock-pydoc")
                             :files ("overblock-pydoc.el")))
#+end_src

Turn the mode on with =M-x overblock-pydoc-mode=. To turn it on in each
Python buffer, add it to =python-base-mode-hook=.

[[file:docs/overblock-pydoc.org::*Use][Use]] in
docs/overblock-pydoc.org tells the commands, the options and the
markup of a project.

** overblock-pycell: Python notebook cells

[[file:img/overblock-pycell.gif]]

=overblock-pycell= shows the results of Python cells in the buffer, as
a notebook does. It needs no Jupyter kernel. The cells go to the Python
interpreter of =python.el=, so the =*Python*= buffer keeps the full
log. The files stay plain Python with =# %%= markers, as jupytext
writes them.

#+begin_src emacs-lisp
  ;; Cells in plain Python files, with the "# %%" convention.
  (use-package code-cells
    :ensure t
    :hook (python-base-mode . code-cells-mode-maybe))

  ;; Figures and tables in the output.
  (use-package comint-mime
    :ensure t
    :hook (inferior-python-mode . comint-mime-setup))

  (use-package overblock-pycell
    :ensure (overblock-pycell :host github
                              :repo ("MArpogaus/overblock" . "overblock-pycell")
                              :files ("overblock-pycell.el"))
    :hook (code-cells-mode . overblock-pycell-mode-maybe))

  ;; IPython gives rich output. Leave out this form where IPython is
  ;; not installed: a plain python3 gives text only.
  (use-package python
    :ensure nil
    :custom
    (python-shell-interpreter "ipython")
    (python-shell-interpreter-args "-i --simple-prompt --no-color-info"))
#+end_src

Open a Python file with =# %%= cells, and run a cell with
=code-cells-eval=. The result shows below the cell. Turn
=overblock-pycell-mode= off, and the blocks go. Then =code-cells-eval=
uses =python-shell-send-region= again.

To run a cell, click the middle run button on its bar.
[[file:docs/overblock-pycell.org::*Use][Use]] in
docs/overblock-pycell.org tells the buttons, the commands, the keymaps
and the options.

** overblock-rmd: R chunks in an Rmd file

[[file:img/overblock-rmd.gif]]

=overblock-rmd-mode= runs the R chunks of an =.Rmd= file and shows the
output under each chunk. The prose between the chunks renders as in
=overblock-md-preview-mode=. There is no knitr run. The chunks go to
the R interpreter of ESS, so the R buffer keeps the full log.

Add =:mode ("\\.[rR]md\\'" . markdown-mode)= to the markdown-mode form
of overblock-md. That line opens an =.Rmd= file in =markdown-mode=.
=poly-markdown+r-mode= of polymode also works.

#+begin_src emacs-lisp
  (use-package overblock-rmd
    :ensure (overblock-rmd :host github
                           :repo ("MArpogaus/overblock" . "overblock-rmd")
                           :files ("overblock-rmd.el"))
    :hook (markdown-mode . overblock-rmd-mode-maybe))
#+end_src

=overblock-rmd-mode-maybe= turns the mode on in a buffer whose file
ends in =.Rmd= or =.rmd=, and does nothing in other buffers. The mode
turns =overblock-md-preview-mode= off, because it renders the prose
itself.

To run a chunk, click the middle run button on its bar.
[[file:docs/overblock-rmd.org::*Use][Use]] in docs/overblock-rmd.org
tells the buttons, the commands and the options.

** Prerequisites

[[*Which One Do You Want]] lists the Emacs packages. The packages also
need:

- Emacs 29.1 or later, with libxml2 for each package that renders
  markup. shr reads the HTML with it.
- A converter from Markdown to HTML, see
  [[file:docs/overblock-md.org::*The converter][=overblock-md-command=]].
  The package uses the first one on =exec-path=. Without a converter or
  without libxml2, the text stays as it is.
- =latex= and =dvisvgm= for the formulas, which latex-to-svg-backend
  runs.
- =pandoc= for =overblock-pydoc=, because both commands of
  =overblock-pydoc-command= are pandoc commands.
- A Python for =overblock-pycell=. Images and tables need IPython and
  comint-mime. A plain =python3= gives text only.
- An R for =overblock-rmd=.
- A nerd font for the icons on the bars. Without one, each button shows
  a plain character or a word.

** Development

=make= runs what the CI runs: byte compilation with warnings as errors,
package-lint, relint and the batch tests. =make test STRICT=1= fails
when a test would skip for a missing tool: a Markdown converter,
markdown-mode, vtable, libxml2 or =sh=. =make test-live= runs the
tests against a real IPython, R and bash, and skips each one that is
not installed. =make scroll= tests the scrolling in a graphic frame. It
runs under =xvfb-run= where that is installed, and else needs a
display.

Install the hooks of =.pre-commit-config.yaml=:

#+begin_src shell
  pre-commit install --install-hooks -t pre-commit -t commit-msg -t pre-push
#+end_src

Before a commit, the hooks check the indentation, the documentation
strings, the declarations and the complexity of each function. Most of
them come from
[[https://github.com/MArpogaus/emacs-pre-commit-hooks][emacs-pre-commit-hooks]].
Before a push, they run package-lint, the compilation and the tests. A
workflow runs the same hooks on each push.

The notes of each package are in =docs/=, one file for each package.
