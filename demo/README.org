#+TITLE: The demo recording

=img/demo.gif= comes from a real Emacs session.  There is no screen
recorder.  Emacs exports its own frame ten times a second with
=x-export-frames=.  The picture therefore has no mouse pointer and no
window decoration.

* What you need

- An Emacs with X support, and a display.  A machine without a
  display can use =Xvfb :99 -screen 0 1280x900x24= and =DISPLAY=:99=.
- IPython, matplotlib and numpy for the cells that make output.
- pandoc for the markdown cells.
- ffmpeg and gifsicle to make the animation from the frames.

The recording asks for Source Code Pro and falls back to whatever
monospace font is installed.  It asks for no nerd font on purpose: the
bars then draw the plain glyphs that `overblock-glyph' falls back to,
which is what the picture has always shown.

* How to record

#+begin_src shell
  emacs -Q -g 101x29 -l demo.el   # writes /tmp/demo/ready, then waits
  touch /tmp/demo/go              # starts the demo and the capture
#+end_src

The size on the command line is not decoration.  =set-frame-size= is a
request, and a bare X server with no window manager can ignore it: six
recordings in a row came out 904x828 instead of 1120x680, with the
markdown wrapped and the animation half as large again, and nothing
said so.  The script now waits for the size, writes what it got to the
trace, and refuses to record a picture of the wrong shape.

The script drives the whole session.  It captures one frame for each
scroll step, and ten frames each second while a view stays.  Nothing
samples on a timer.  The motion in the frames is therefore as even as
the steps that made it.

The script writes a trace of the stages to =/tmp/demo/trace=.  A pan
that stops too early reports this there.

* How to build the animation

The frames are one sequence in the order of the recording, and this
includes the pan:

#+begin_src shell
  ffmpeg -framerate 13 -start_number 1 -i frames/f%04d.png \
      -filter_complex "[0:v]tpad=stop_mode=clone:stop_duration=2.5,\
                       scale=820:-1:flags=lanczos,split[a][b];\
                       [a]palettegen=max_colors=128[p];[b][p]paletteuse" \
      -loop 0 raw.gif
  gifsicle -O3 --lossy=80 raw.gif -o ../img/demo.gif
#+end_src

Each frame stands for a tenth of a second.  A rate of thirteen frames
each second sets the pace.

Do not resample with the =fps= filter.  It drops frames in an
irregular way, and the motion becomes uneven.

The =tpad= filter holds the last view.  The restart of the loop then
reads as a restart, and not as a jump.
