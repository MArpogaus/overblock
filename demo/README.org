* Demo Recording

=img/demo.gif= is recorded from a real Emacs, without a screen recorder.
Emacs exports its own frame ten times a second through =x-export-frames=,
which keeps the mouse pointer and the window decoration out of the
picture.

** What You Need

- Emacs with X support, and a display.  A headless machine can use
  =Xvfb :99 -screen 0 1280x900x24= and =DISPLAY=:99=.
- IPython, matplotlib and numpy, for the cells that produce output.
- pandoc, for the markdown cells.
- ffmpeg and gifsicle, to turn the frames into the animation.

** How to Record

#+begin_src shell
  emacs -Q -l demo.el          # writes /tmp/demo/ready, then waits
  touch /tmp/demo/go           # starts the demo and the frame capture
#+end_src

The script drives the whole session and captures deterministically:
one frame per scroll step, and ten frames per second while a state is
held.  The final pan is recorded downwards into =frames-pan/= and the
animation plays it in reverse: scrolling up across the first markdown
block trips an Emacs measurement bug (see Known Limits in the main
README), scrolling down does not.  Nothing samples on a timer, so the motion in the frames is as
even as the steps that produced it.  A trace of the stages lands in
=/tmp/demo/trace=.

** How to Build the Animation

Put the main frames and the reversed pan into one sequence first; the
trace names the frame where the pan starts:

#+begin_src shell
  mkdir -p seq && n=0
  last=$(grep -oP 'f\K[0-9]+(?= scroll up)' /tmp/demo/trace)
  for f in $(ls frames/f*.png | head -n "$last"; ls frames-pan/p*.png | sort -r)
  do cp "$f" "seq/s$(printf %04d $((++n))).png"; done
#+end_src

#+begin_src shell
  ffmpeg -framerate 13 -start_number 1 -i seq/s%04d.png \
      -filter_complex "[0:v]tpad=stop_mode=clone:stop_duration=2.5,\
                       scale=820:-1:flags=lanczos,split[a][b];\
                       [a]palettegen=max_colors=128[p];[b][p]paletteuse" \
      -loop 0 raw.gif
  gifsicle -O3 --lossy=80 raw.gif -o ../img/demo.gif
#+end_src

The frames stand for a tenth of a second each; playing them at
thirteen per second sets the pace.  Never resample with the =fps=
filter: it drops every few frames unevenly and the motion stutters.
The =tpad= holds the final view, so the loop restart reads as a
restart and not as a jump.
